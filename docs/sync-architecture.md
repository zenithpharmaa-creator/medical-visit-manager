# تصميم نظام المزامنة المركزية

## الهدف

ربط أجهزة مدير النظام والمندوبين بخادم مركزي بحيث تبقى بيانات الجهات والزيارات والخطط متاحة محلياً، وتُرسل التغييرات تلقائياً عند توفر الإنترنت، مع منع فقدان البيانات وإظهار التعارضات للمدير.

## البنية المقترحة

يتكون النظام من أربعة أجزاء مترابطة:

1. **قاعدة محلية على الجهاز:** تحفظ الجهات والزيارات والخطط وطابور التغييرات عندما يكون الجهاز دون اتصال.
2. **عميل مزامنة:** يراقب الاتصال، يرسل العناصر غير المرسلة على دفعات صغيرة، ويعيد المحاولة بتأخير تصاعدي.
3. **واجهة API محمية:** تستقبل الدفعات، تتحقق من الجهاز والمندوب، وتعيد المقبول والتعارضات وآخر نسخة مركزية.
4. **قاعدة مركزية:** تحفظ أحدث نسخة من كل سجل، وإصداره، وسجل التغييرات، وحالة كل جهاز.

## دورة المزامنة

عند إنشاء أو تعديل زيارة أو جهة أو خطة، يُحفظ التغيير محلياً أولاً مع `changeId` فريد و`baseVersion`. وعند عودة الاتصال، يرسل الجهاز الدفعة إلى الخادم. يتحقق الخادم من رمز الجهاز، ثم يعالج كل تغيير داخل معاملة قاعدة بيانات؛ التغيير المقبول يرفع إصدار السجل، أما اختلاف `baseVersion` فيُسجل كتعارض ولا يُستبدل بصمت. بعد ذلك يعيد الخادم السجلات المحدثة والتعارضات، فيطبق الجهاز المقبول محلياً ويضع التعارض في قائمة مراجعة المدير.

## سياسة التعارض

| نوع البيانات | السياسة الافتراضية               | قرار المدير                            |
| ------------ | -------------------------------- | -------------------------------------- |
| زيارة جديدة  | قبول إذا كان `changeId` جديداً   | لا يلزم تدخل غالباً                    |
| تعديل زيارة  | تعارض عند اختلاف الإصدار الأساسي | اعتماد نسخة الجهاز أو الخادم مع ملاحظة |
| جهة أو خطة   | عرض النسختين والفروق             | اختيار نسخة أو دمج الحقول              |
| حذف          | حذف منطقي فقط                    | استعادة أو اعتماد الحذف                |

## الأمان

يُفعّل الجهاز برمز قصير العمر يُستخدم مرة واحدة. يُخزن الخادم تجزئة رمز الجهاز لا الرمز نفسه، ويُرسل الجهاز الرمز عبر HTTPS. يجب ربط كل جهاز بمندوب، وإتاحة إلغاء الجهاز من حساب المدير، والتحقق من الصلاحية قبل كل دفعة، ومنع إعادة تنفيذ التغيير عبر `changeId` الفريد. لا تُحفظ كلمات المرور أو رموز الأجهزة في سجلات التطبيق.

## ما هو موجود حالياً في المشروع

المشروع يحتوي بالفعل على أساس الخادم: جداول `sync_devices` و`sync_activation_codes` و`sync_records` و`sync_changes`، وإنشاء رموز تفعيل، وتسجيل الأجهزة، وإلغاء الجهاز، وواجهة `sync.pushPull` لمعالجة دفعات تصل إلى 100 تغيير، وإرجاع التعارضات والسجلات المركزية. هذا الأساس لا يعني أن المزامنة التلقائية من واجهة التطبيق مكتملة بعد.

## مراحل التنفيذ التالية

1. إضافة مخزن محلي لطابور التغييرات باستخدام AsyncStorage أو SQLite، مع حالات `pending`, `sending`, `synced`, `conflict`, و`failed`.
2. إضافة مستمع اتصال يعيد المحاولة عند عودة الشبكة، مع حد أقصى للدفعة وتراجع تصاعدي.
3. ربط إنشاء وتعديل وحذف الجهات والزيارات والخطط بإضافة عناصر للطابور.
4. إضافة شاشة حالة المزامنة وسجل العمليات والتعارضات للمدير.
5. إضافة أدوات اعتماد التعارض مع حقل ملاحظة وسجل تدقيق.
6. تقييد `pushPull` بإجراء مصادق عليه أو رمز جهاز صالح، ثم إضافة اختبارات انقطاع الشبكة وإعادة المحاولة والتعارض.

## مبدأ مهم

يجب أن تكون الكتابة المحلية هي الخطوة الأولى دائماً؛ لا يمنع انقطاع الإنترنت تسجيل زيارة. ولا تُعتبر الزيارة متزامنة حتى يؤكد الخادم قبولها، مع إبقاء نسخة محلية قابلة لإعادة الإرسال.
